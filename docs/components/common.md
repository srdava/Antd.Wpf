# 全组件共同要求

适用范围：本目录73个核心入口和外部Pro组合要求。目标`net48;net8.0-windows`；参考Ant Design6.6.8。各组件的属性名是本项目拟定接口，必须经过M0及组件切片验证后冻结，不应直接批量生成所有属性。

## 1. 分析与实现的区别

本轮逐项读取了官方Markdown的使用说明、示例目录、API、子组件及相关FAQ。原始资料与URL/hash见[73项来源清单](../analysis/official/manifest.json)。这属于官方文档分析，不表示已逐示例操作浏览器，更不表示WPF已经运行。

每个规格分为官网事实与WPF要求。源码尚未实现的事项必须写成要求/拟定契约，原型验证点不能记为通过。首期、后续和不适用能力均需有明确处置，不能把“以后再做”当成已实现。

## 2. 批次、交付范围与API映射

- P0：主题、Owner/AntHost、公共资源和最小构建基础。
- P1：首个可用版本的组件基础；它不是整个组件所有子能力的完成承诺。
- P2：核心1.0扩展，含复杂选择、日期时间、弹层和平面数据表。
- P3：后续大数据/复杂布局/高级组合/装饰能力，单独估算。
- React专有类型工具、DOM样式和路由参数按WPF能力替代或明确不适用，不制造同名空控件。
- `Variant/Size/Status`等统一语义由实际组件适用性决定；WPF原生已有的IsEnabled、IsReadOnly、IsChecked、SelectedItem等属性保持原义。

## 3. 视觉与状态

- 用户要求与原Antd保持间距、圆角、颜色和风格一致。默认值以固定6.6.8最终样式与实际token算法为依据，见[视觉token映射](../analysis/visual-token-mapping.md)；必须区分中间token和最终CSS、控件默认Margin和Gallery布局Margin。未知/尚未复刻的模糊阴影、字体栅格、动画和状态组合必须记录，不能笼统宣布逐像素一致。
- Light/Dark、三种常用尺寸及Compact统一来自主题资源；局部token覆盖遵循[架构资源优先级](../architecture/README.md)。首批不保证官网自定义主题/所有预设颜色逐像素相同。
- Default/Hover/Pressed/Focus/Disabled按交互类型实现；输入另覆盖ReadOnly/Empty/Error/Warning；异步操作覆盖Loading/Failure/Canceled。
- 优先级：禁用约束交互，其次只读约束编辑；选中/检查和错误可同时存在，错误不能抹掉焦点指示；最终状态组合在Gallery展示。
- 100%/125%/150%/200%DPI、中文/英文、长文本、字体放大均验证；24/32/40DIP不是强制裁剪内容的固定高度。
- 使用FlowDirection继承进行RTL布局；对左右箭头、方向按键、分割器等需要镜像的行为逐项验证，图标/文本不应无差别翻转。

## 4. 绑定、输入、数据与参数

- 保留外部Binding、DynamicResource和用户LocalValue；内部修改状态不得用简单赋值摧毁绑定。数据值、显示文本、选中Key与位置索引分开。
- 状态集合按实例创建，避免可变DependencyProperty默认集合跨实例共享。ItemContainer回收先解除旧数据/订阅，再绑定新项。
- 明确本组件单向/双向属性和Text更新时机。IME组合输入不提前触发搜索或提交，撤销/重做/选区与剪贴板行为保留。
- 编程参数的非法域（负页大小、负时长等）由验证拒绝并给出明确错误；数据/集合变化导致的暂时失效（当前索引超出新集合）通过Coerce/钳制或清空按组件约定恢复；用户编辑中间态属于校验状态，不能当异常抛出。
- 服务器操作通过宿主命令/回调执行。请求取消、过期结果、超时、重试/失败、卸载与再次加载需要明确；库不隐式访问数据库或上传服务。

## 5. 模板与生命周期

- 原生模板PART与滚动/键盘/自动化机制要保留。重模板化解绑旧PART；可选PART缺失应有可用降级，必需PART缺失给出可定位诊断。
- 所有计时器、订阅、Popup、CancellationTokenSource、异步操作记录所有者与结束路径。Unloaded可能只是临时卸载，重新Loaded开启新的加载代次，旧回调不能修改新代次。
- 库仅管理自己创建/拥有的资源；调用者提供的VM、流、控件、ImageSource和业务订阅保留调用者所有权，除非接口明确移交。
- 定位目标允许显式传入PlacementTarget/ScrollTarget等引用；不暴露内部视觉树作为数据API，不以全局搜索窗口来推断Owner。

## 6. 可访问性与验收

- 所有交互提供键盘路径、可见焦点和语义AutomationPeer；IsEnabled/ReadOnly/选中值正确被辅助技术感知。
- Esc/Enter/Space/方向键/Home/End按组件语义处理；遵守AccessKey、焦点顺序、Label关联。高对比度与关闭动画后仍能区分状态。
- 每个组件至少包含三项本地验收场景；复杂组件还需失败/取消、数据更新和边界组合。验收对象是用户可观察结果，不仅是DependencyProperty存在。
- 性能敏感组件必须遵守[性能契约](../architecture/performance.md)，说明哪些功能组合保持虚拟化，哪些属于未承诺范围。
- 发布前同一行为分别在Framework和现代.NET宿主验证；不能以其中一端通过代替另一端。

所有后续实现任务应引用“组件slug + 本批功能 + 验收场景ID/序号 + 性能场景”。这样可以评估完成度与回归范围，而不依赖一句“实现Antd风格”。
